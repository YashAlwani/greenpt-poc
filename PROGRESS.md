## What was built

### Pipeline runtime — LangGraph 3-node graph

**DL reference:** DL-01 (`decision_logs/01_langgraph_3_agent_architecture.txt`)

```
simulate_node  →  greentpt_node  →  eval_node  ──(rows_remaining?)──▶ loop / END
```

| File | Lines | Role |
|------|-------|------|
| `graph.py` | 22 | Wires the three nodes; `build_graph()` returns compiled `StateGraph` |
| `state.py` | 25 | `BenchmarkState` TypedDict — single source of truth for row state |
| `nodes/simulate.py` | 33 | Pops next row from `rows_remaining` into `current_row` |
| `nodes/greentpt.py` | 24 | Calls all 4 method tools against `current_row`, stores in `method_results` |
| `nodes/eval.py` | 67 | Schema check + G-Eval score + conditional edge `should_continue` at `:63` |

### TOON compression engine

**DL reference:** DL-00 (`decision_logs/00_poc_scope_and_ruleset.txt`)

| File | Key functions |
|------|---------------|
| `toon.py` | `build_key_map(:56)`, `encode(:84)`, `decode(:90)`, `compress(:97)` |

The abbreviation threshold is `MIN_KEY_LEN_TO_ABBREVIATE = 4` (`toon.py:53`) — compressing shorter keys saves at most 1 token at the cost of readability.

### Four optimization methods

**DL reference:** DL-00, DL-01

All implemented in `tools/greentpt_tools.py`. Fairness constants (`TEMPERATURE = 0`, `MAX_TOKENS = 1024`) defined as module-level constants so they cannot drift between methods.

| Function | Lines | Method |
|----------|-------|--------|
| `call_baseline(:122)` | 13 | green-l-raw + vanilla system prompt |
| `call_postprocess(:135)` | 17 | green-l-raw + client-side TOON after the call |
| `call_prompt_engineering(:152)` | 12 | green-l (tuned system prompt only) |
| `call_combined(:164)` | 27 | green-l + TOON key_map injected into user message |

## What this POC enables next

1. **Smart routing v1** — replace `sdk.py:31` heuristic with use-case-aware logic from DL-04 findings (never default to `prompt_engineering`; prefer `combined` for invoice/resume schemas, `postprocess` for short outputs)
2. **green-l system-prompt tuning** — DL-03 identified that adding a "be terse" instruction to green-l's system prompt would flip `prompt_engineering` from −15% to net-positive without touching quality
3. **green-r benchmark** — same 48 rows, same methodology, ~€0.10 estimated cost (scoped in DL-09)
4. **Server-side TOON injection** — moving `_toon_user_prefix` into the GreenPT system prompt eliminates the ~80-token overhead that makes `combined` lose on tiny outputs (DL-04)
